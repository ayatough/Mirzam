# Mirzam を Marp・Touying と並べる

> これは [docs/comparison.md](../comparison.md) の日本語訳であり、原文が正です。
> 2026-08 時点のスナップショットで、三者とも開発中のため個別の事実は古くなり得ます。
> これは優劣表ではありません — どのツールも自分の狙いをよく果たしています。
> ポジショニング判断のための「賭けの違いの地図」です。

テキストから始まるスライドツールが三つ。同じ問い — *デッキの視覚的な半分はどこに
住むのか* — への答えが三通りあります。

- **[Marp](https://github.com/marp-team/marp-cli)** (Node.js、2016〜):
  *テーマ CSS* に住む。Markdown は内容だけを持ち、レイアウトとデザインはテーマ
  作者の仕事。コアの Marpit は「事前定義クラスなし、純粋な CSS」を方針として明言。
- **[Touying](https://github.com/touying-typ/touying)** (Typst パッケージ):
  *プログラム* に住む。デッキは Typst ソース — 関数・クロージャ・組版プリミティブを
  持つ本物の言語 — なので、コードで書けるものはスライドに書ける。
- **Mirzam** (Rust): *文書* に住む。レイアウト・チャート・コネクタ・アニメーションの
  順序が Markdown ファイル自体に、プレーンパーサではコードブロックに退化する
  ブロックとして書かれる。

## 共通点

三者とも: git で diff できるプレーンテキストのソース、軽量マークアップからの
スライド生成、CSS またはコードによるテーマ、逐次表示、発表者ノート、数式、
PDF 出力、watch / プレビューのループ。

## 一覧

| | Marp | Touying | Mirzam |
|---|---|---|---|
| ソースの言語 | Markdown | Typst | Markdown |
| 動作環境 | Node.js (PDF はブラウザ) | Typst コンパイラ (Rust) | 単一 Rust バイナリ / WASM |
| 一次出力 | HTML | PDF | 単一ファイル HTML |
| PDF | ブラウザ経由 | ネイティブ | Chromium 印刷 |
| PPTX | あり (ラスタ、編集可能は実験的) | touying-exporter 経由 | 計画中 |
| レイアウト制御 | テーマ CSS / 生 HTML | 組版コード (`grid`, `place`) | ASCII ペイングリッド |
| スライド間トランジション | View Transitions API (33 種) | — (PDF ページ) | transition DSL |
| スライド内アニメーション | fragmented list | `#pause` `#only` `#uncover` `#alternatives` — ステップがページになる | `anim` タイムライン DSL + 上演専用 `effects` |
| データからのチャート | プラグイン経由 | プログラマブル (CeTZ 系) | CSV から `chart` ブロック、マーク毎の安定 id |
| 動画 / 音声 | HTML 埋め込み | — (PDF。HTML エクスポータで GIF) | `<video>`/`<audio>` インライン化、YouTube/Vimeo |
| 拡張性 | markdown-it プラグイン | 言語まるごと + Typst Universe | 組み込み DSL のみ (意図的) |
| 学習コスト | 最小 | 最大 | 中間 |

## Marp と並べる

重なりは実在します — Markdown、`---` 区切り、CSS テーマ、HTML と PDF — が、
それは両ツールの最も薄い層です。分かれるのは:

- **レイアウト。** Marp はテーマに委ね、複数カラムはテーマ CSS か Markdown 内の
  生 HTML になる。Mirzam はペイングリッドで文書内に留める。これが最大の違いで、
  Marpit が最小主義を方針として明言している以上、埋まりにくい違いでもある。
- **動き。** Marp のスライド間トランジション (View Transitions API、ブラウザ
  ネイティブ) は洗練されており、逐次表示は fragmented list で足りる。Mirzam は
  スライド内タイムライン (要素・文字単位、スプリング) を持ち、文書のアニメーションと
  上演専用エフェクトを区別する。
- **データ。** Marp に組み込みチャートはない。Mirzam は CSV からビルド時に生成し、
  全マークに参照可能な id を振る。
- **裾野。** Marp には 10 年分のテーマ・回答・CI アクション・PPTX 出力があり、
  VS Code 拡張は広く普及している。Mirzam にはないエコシステムの重力。
- **速度。** 普通のデッキなら両者とも十分速い。Mirzam のスライド単位キャッシュ
  (編集ごとの再レンダリングは厳密に 1 スライド、20 枚のフルビルド 4.5 ms) が効くのは
  大規模デッキ、エディタ内プレビュー、CI。

## Touying と並べる

素の能力では Touying が三者で最強です。Typst のすべて — 本物のプログラミング言語、
本物の組版エンジン、Typst Universe のパッケージ群 (図の CeTZ、矢印の fletcher、
プロットライブラリ) — を継承しているからです。アニメーションモデルも美しい:
`#pause` `#only` `#uncover` `#alternatives` は数式の中でも使え、各ステップが PDF の
1 ページにコンパイルされるので、PDF が開く場所ならどこでも発表でき、handout モードで
綺麗に畳まれる。分かれるのは:

- **言語。** Typst は Touying の力であり代価でもある。すべてがプログラマブル —
  テーマもコード、図もコード — でプログラマに向き、投資に報いる。ただしこのために
  覚える記法であり、ソースは Typst ツールの外ではどこにもレンダリングされない。
  Mirzam のソースは GitHub・エディタ・Obsidian が既に表示できる Markdown。
  天井は低いが、床がずっと高い。
- **出力の向き。** Touying は PDF ファースト。HTML と PPTX は SVG ページを
  impress.js で包む別途エクスポータから来る。Mirzam は HTML ファースト — 動画・
  音声・ライブ解決コネクタ・プレゼンター窓 — で、PDF は同じ HTML の印刷。どちらが
  正しいかは会場次第: PDF はどのマシンでも発表でき、HTML デッキはメディアと動きを
  運べる。
- **ページとしてのアニメーション vs ランタイムとしてのアニメーション。** Touying の
  ステップは追加ページ: 堅牢で可搬だが、逐次表示のたびに物理ページ数が増え、状態間の
  「動き」はモデルに含まれない。Mirzam のステップはレイアウト済みの 1 スライド上の
  ランタイム状態: スプリングも stagger もあり、フラグメント間でチャートは再描画されず、
  PDF は各スライドを全露出で見せる。
- **タイポグラフィ。** Typst は本物の組版エンジンで両端揃え・ハイフネーション・数式を
  組む — 印刷品質はホームグラウンド。Mirzam は意図的にタイポグラフィをブラウザに
  委ね、コアは幾何に徹する。
- **大規模時のパフォーマンス。** Typst はミリ秒でコンパイルし、Touying は Polylux を
  遅くしていた counter/locate のコストを避けている。実際には、`#pause` の多いデッキは
  多数の物理ページに増殖し、文書全体にまたがる機能 (目次・参照・グローバル状態) が
  その全体で再計算される — 大きなデッキが遅く・不安定になり得るのはここで、Typst も
  Touying も活発に最適化しているため最新版での再検証の価値はあります。Mirzam の
  作業単位はスライドで、キャッシュが「編集 = 1 スライド再レンダリング」を保証し
  (500 枚でフルビルド 75.6 ms / 編集 3.2 ms)、クリックステップはページではなく
  ランタイム状態。
- **検証。** どちらも CI でビルドはできる。Mirzam の `check-layout` はさらにデッキを
  実レンダリングして、ペインのはみ出し・重なり・死んだコネクタ / 注釈参照で CI を
  落とす — レイアウトと参照がコードではなく構造化データだから成立するチェック。

## Mirzam の差別化ポイント

他の二者が空けている場所 — 断定ではなく方向性として、短く:

1. **文書 → デッキ。** 退化保証 + `--split h2` により、README や設計メモが無編集で
   デッキになる。Marp はスライドを*書く*ツール、Touying はスライドを*プログラムする*
   ツール、Mirzam は*書いてあったもの*をスライドにするツール。
2. **レイアウトは描く。** スタイルシートでもコードでもなく。ASCII グリッドは
   Marp の「CSS を書け」と Touying の「コードを書け」の間の第三の道。
3. **住所を持つデータ。** CSV からのチャートで、コネクタや注釈が 1 本の棒を指せる。
   スクリーンショットなしで文章と根拠が結ばれる。
4. **HTML ネイティブな発表。** 自己完結の単一ファイル、メディアのインライン化、
   `?presenter=1` で開き直すだけのプレゼンター窓、上演にしか存在しないエフェクト。
5. **CI が却下できるデッキ。** レイアウト検査・退化テスト・ライト / ダークの
   トークン対称性が推奨ではなく強制 — コーディングエージェントがデッキを書く
   ワークフローの安全な土台にもなる。
6. **覚える言語がない — 寄りかかる言語もない。** Mirzam は意図的にプログラマブルで
   ない。スライドにクロージャが欲しい人は Touying の観客であり、そこを追えば
   肝心の単純さを失う。

## 要約

Marp は文書を最小に保ち、視覚を CSS に置く。Touying は文書をプログラムにし、視覚を
コードに置く。Mirzam は文書をプレーンに保ったまま、レイアウト・データ・動きを
構造化された検証可能なテキストとして文書の中に移す。三者ともマークアップをスライドに
変えるところまでは同じで、その扉の先で別々の方向に歩いていきます。
