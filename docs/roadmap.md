# Mirzam ロードマップと MVP 定義

## 1. MVP(v0.1)の定義

### ゴール

**「自分の次の発表資料を、Marp の代わりに Mirzam だけで作りきれる」**

差別化の核である 3 点 — ①ASCII ペインレイアウト、②ページ単位の軽量インクリメンタルプレビュー、③プレーン Markdown 互換 — を最小構成で成立させ、日常利用でドッグフーディングを開始する。

### MVP に含むもの

| # | 機能 | 受け入れ基準 |
|---|---|---|
| 1 | CommonMark + frontmatter + `---` スライド分割 | 既存の Marp 原稿(基本構文のみ)がほぼ無修正で表示できる |
| 2 | ファイル分割 `![[file.md]]` | セクション別ファイルを結合して 1 デッキにできる。循環参照はエラー表示 |
| 3 | `pane` ブロック + `::: pane` 割り当て | ASCII グリッドどおりの比率でレイアウトされる。未割当ブロックは既定ペインへ |
| 4 | 画像配置 | `pane=` / `fit=contain|cover` / `w=` / `align=` が機能する |
| 5 | インライン属性 `{#id .class}` / 変数 `{{var}}` と四則演算 | frontmatter の vars が本文・表内で展開される |
| 6 | 数式(KaTeX) | `$...$` / `$$...$$` が描画される |
| 7 | `mirzam serve`(ホットリロード) | 保存 → 変更スライドのみ再描画。**100 スライドのデッキで編集反映 100ms 以内**(計測をベンチとして常設) |
| 8 | `mirzam build`(静的 HTML) | 単一フォルダで配布可能な HTML が出る。キーボードでページ送り |
| 9 | `mirzam export pdf` | ヘッドレス Chromium 経由で HTML と同一見た目の PDF が出る |
| 10 | スピーカーノート(記法+収集) | `<!-- note: -->` がパースされ、serve 中に `N` キーでノートパネル表示 |
| 11 | 組み込みテーマ 1 種 + CSS カスタム | CSS variables 上書きで色・フォントを変えられる |

### MVP でやらないこと(明示的な非ゴール)

- shape / connect / anim ブロック(構文は**パースだけ**して「未対応」表示 — 前方互換のため)
- 発表者モード(別ウィンドウ・タイマー・ポインタ)
- VSCode / Obsidian 拡張(プレビューはブラウザで代替)
- PPTX / Google スライドエクスポート
- プラグイン API、Typst Math、動画(※ `<video>` がそのまま HTML に通る分は動く)
- モバイル編集

### MVP の成果物

- `mirzam` CLI バイナリ(build / serve / export pdf)
- crates: `mirzam-syntax` / `mirzam-core` / `mirzam-layout` / `mirzam-render` / `mirzam-cli`
- `web/runtime`(最小ビューア JS)
- examples/ のサンプルデッキがそのまま回帰テスト(スナップショットテスト)になる

## 2. フェーズ計画

規模感: S = 数日、M = 1〜2 週間、L = 3 週間以上(1 人開発想定の目安)。

### Phase 0: スパイク(規模 M)← 今ここ

設計リスクの高い 2 点を先に潰す。

- [x] パーサ基盤: スパイクは comrak で実装(GFM 拡張 + raw HTML がそのまま使え、追加実装ゼロで通った)。fenced div / インライン属性はソースレベル前処理で実現できたため、markdown-rs との本格比較は AST 変換が必要になる Phase 2(プラグイン設計)まで保留
- [x] ASCII グリッドパーサのプロトタイプ + 単体テスト(結合セル・矩形性検証・行高比率)
- [ ] スライド分割 + ハッシュキャッシュの骨組みで「差分パース」を実証(→ Phase 1 の serve 実装と合流)
- [ ] 記法仕様 v0 を実物フィードバックで v0.1 に改訂

**完了条件**: `examples/demo.md` が(素の HTML で)レイアウト付きレンダリングされるデモが動く。→ **達成**(`cargo run -p mirzam-cli -- build examples/demo.md`、5 スライド 約10ms、単一ファイル HTML 出力)

### Phase 1: MVP v0.1(規模 L)

上記 MVP 表の全項目。マイルストーン順:

1. パイプライン縦通し(parse → IR → layout → HTML、単一スライド)
2. デッキ化(分割・include・テーマ・ビューア JS)
3. serve + インクリメンタル更新 + ベンチ常設
4. PDF エクスポート、ノート、変数、KaTeX
5. ドッグフーディング(実発表 1 本を Mirzam で作る)→ フィードバック反映

### Phase 2: 図形とコネクタ、エディタ統合(規模 L)

- `shape` ブロック(SVG レイヤ)
- `connect` ブロック: アンカー解決・自動ルーティング・リサイズ追従(`mirzam-connect`、WASM 共有)
- 動画 / GIF の正式サポート(属性・PDF 時ポスター置換)
- `mirzam-wasm` + VSCode 拡張(Webview ライブプレビュー)

### Phase 3: アニメーションと発表体験(規模 L)

- `anim` ブロック → タイムライン IR → Web Animations API(文字単位分解、stagger、spring)
- ページ切り替えトランジション
- 発表者モード(ノート・次スライド・タイマー・ポインタ)
- `mirzam-lsp`(補完・未定義参照診断)→ VSCode 拡張に統合

### Phase 4: 拡張性(規模 M〜L)

- プラグイン API(コア: WASM AST パス / ランタイム: JS エフェクト)
- Typst Math 対応、テーマエコシステム(テーママニフェスト)
- 表計算的機能の拡充(列集計など)

### Phase 5: エコシステム到達(規模 L+)

- PPTX エクスポート(変換不能要素は画像化フォールバック)、Google スライドは PPTX 経由 or API
- Obsidian プラグイン
- ブラウザ編集環境(PWA)→ スマホ編集
- PDF 直接生成(組版エンジン導入)の検討

## 3. 品質ゲート(全フェーズ共通)

- **互換性テスト**: 全サンプルを素の CommonMark パーサに通し「壊れない」ことを CI で検証(大原則の自動化)
- **スナップショットテスト**: デッキ → HTML 出力のゴールデンテスト
- **等価性テスト**: インクリメンタルビルド結果 ≡ フルビルド結果
- **性能ベンチ**: 100 / 500 スライドの合成デッキで、フルビルド時間と単一スライド編集反映時間を計測し続ける

## 4. 直近のアクション

1. Phase 0 スパイク開始: cargo workspace 初期化、`mirzam-syntax` でパーサ比較
2. ASCII グリッドパーサ実装 + テスト
3. `examples/demo.md` を最初のゴールデンテスト入力に昇格
