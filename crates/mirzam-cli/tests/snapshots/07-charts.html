Charts

Six kinds, from CSV written in the slide. Every mark has a name, so an arrow can point at one of them.

This deck owns the chart block. Shapes, connectors and the rest are in 04-components.md.

Data in, chart out

Both charts are written as CSV in the slide; no image files involved.

Charts

An axis that measures

  • minute holds numbers, so the axis measures: the hour between 15 and 60 is drawn as the hour it is, not as one more step
  • A column of labels — W1, 2024 Q1 — keeps the even spacing it always had
  • x: names the column, so a file whose value columns come first needs no editing to be plotted

The tail is flat and sparse; on an evenly spaced axis it would read as a much faster recovery than it was.

Charts

Stacked two ways

Same data, two questions. true takes the axis to the tallest column; percent fills every column, so the segments read as shares of it.

Charts

On its side

  • A column chart is bad at exactly this: a name worth reading has nowhere to go under a column
  • The side margin grows to hold the longest one
  • The ranked list these usually are reads top to bottom anyway

horizontal: true. Stacking works the same way along the row.

Charts

Points, with nothing joining them

type: scatter is a line chart without the line: the same value axis, the same marks, the same ids.

Its x column is numbers, so the points sit where the numbers put them — which is the whole reason to draw one.

Everything the value axis learned applies here; a scatter is what needed it.

Charts

A pie, and a pie with a hole

inner: is a fraction of the radius. From 0.45 up the hole carries the total, which a pie has nowhere else to put.

Charts

Three dimensions, still vector

The points are projected at build time and emitted as ordinary marks, so this prints to PDF at any resolution and ships no code to the browser.

azim and elev turn an orthographic camera. The three faces turned away are the ones drawn, so the box is never in front of the data.

Points only, and no rotating it in the viewer: both deliberate, and both written down in docs/syntax.md.

Charts

Every mark has a name

Every mark has a name: the chart's id, the series and the row. #runs-1-0 is the first point of the second series — and an annotation can be tied to it without knowing it came out of a projection.

It holds from every camera angle, because turning the camera changes which disc is drawn over which and nothing else. A picture of a chart cannot offer that.

The pairing, not an arrow: both halves are one annotation with the same step, so they arrive together in one colour and nothing crosses the slide. The circle is placed from the mark's live box, which is how it reaches a point that only exists once the projection has run.
