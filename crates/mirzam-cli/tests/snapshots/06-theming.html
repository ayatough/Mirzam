Theming and settings

Every knob a deck has, and the order they are read in. This deck sets four of them on itself: theme: [mirzam, themes/blueprint.css] — the built-in for its own colours and type, and a theme of somebody's own for one pane to wear later — math: typst for how its one formula is written, and footer: for the line along the bottom of every slide after this one.

Press D. The whole deck flips, because every theme defines both modes - the built-in one this deck wears, and the one it loads from a file for a single pane. This slide says chrome: none, which is why the footer starts on slide 2.

Light and dark

Four ways to choose a mode

  1. mode: dark in frontmatter
  2. ?mode=dark in the URL
  3. D in the viewer
  4. the reader's prefers-color-scheme

First one that is set wins.

mode: is baked into the file, so a deck that must be dark never flashes white while it loads.

Leave it unset and the deck follows the machine it is opened on, live, with no reload — which is usually what you want for something you are emailing to somebody.

D only lasts for that reading session; it changes nothing on disk.

Reference

Every frontmatter field

---
title: Quarterly review
author: Your Name
theme: [mirzam, themes/house.css]
mode: dark
aspect: "16:9"
split: h2
transition: fade 240ms
fit: shrink
math: typst
vars:
  seats: 8
---
  • All optional; a deck with no frontmatter builds
  • theme: takes a built-in name, a .css path relative to the deck file, or a list of both in cascade order
  • split: starts a slide at every heading of that level
  • transition: is the deck-wide page turn; a slide can override its half
  • math: picks the formula syntax, latex (the default) or typst
  • vars: are substituted with {{ }}, and arithmetic works: {{ seats * 12 }}

Per element

Settings smaller than a deck

## Heading {#intro .center}

[a phrase]{#win .u}

::: pane hero {.card valign=middle}
Content of the pane.
:::

An attribute block takes an #id, any number of .classes, and key=value pairs.

  • On a heading or a span: the id a connector or an annotation points at, and the classes your stylesheet styles
  • On a pane: align, valign, bg, dim, blur, scrim, fit
  • .center, .right, .small, .u, .box, .card, .eyebrow and .metric come with the renderer; anything else is yours to define

In a plain Markdown reader the braces are literal text — that is the price, and the reason the syntax is this quiet.

theme: takes a file, and the file gets a name

---
theme: [mirzam, themes/blueprint.css]
---

::: pane fig {theme=blueprint}
  • An entry ending in .css is a path, relative to the deck
  • A list is cascade order; your file loads last, over the type

This pane is theme=blueprint

A stem is only a name if the file scopes its tokens to it: [data-theme="blueprint"] { … }. A file that writes :root themes the whole deck and answers to nobody — and mirzam check says so.

  • Mono display type, an em-dash bullet
  • Square cards, a hairline rule

examples/themes/blueprint.css is the whole theme, in tokens.

The right-hand pane is the point of the whole feature: a theme nobody built in, applied to one pane by name, carrying its type as well as its colours. That works because tokens inherit and rules do not.

A theme of your own

Override the tokens, not the layout

:root {
  --mz-slide-bg: #0d1117;
  --mz-fg: #e9edf5;
  --mz-accent1: #5b8cff;
  --mz-accent2: #2dd4bf;
}
:root[data-mode="light"] {
  --mz-slide-bg: #ffffff;
  --mz-fg: #17202a;
  --mz-accent1: #2f5fe0;
  --mz-accent2: #0f766e;
}

The built-in tokens carry no specificity, which is what lets a plain :root beat them — and is why a stylesheet that sets its colours once pins the deck to one mode. D then changes data-mode and nothing moves.

Set every token in both blocks, or set none and let the theme do it.

mirzam check holds your theme to that rule, and a test holds examples/themes/*.css to it.

Theming and settings10 / 16

A theme of your own

Margins are tokens too

:root {
  --mz-grid-pad-y: 56px;
  --mz-grid-pad-x: 72px;
  --mz-grid-gap: 28px;
}
.framed {
  --mz-pane-border: 1px solid var(--mz-border);
  --mz-pane-radius: 8px;
  --mz-pane-pad: 14px 18px;
}

::: pane fig {.framed}

Six tokens set a deck's margins, the gap between panes, and the padding, border and radius of a pane. Every one carries its built-in value as a fallback, so a deck that sets none renders exactly as it always did.

These are not palette tokens — no built-in theme defines one, and theme: stays a choice of colour.

Because custom properties inherit, the same names work at any scale: on :root they move the deck, on a class you put on one pane they move that pane.

The theme this deck wears sets the first three as tokens. A deck anchoring shapes to panes declares them in frontmatter instead, because the build computes pane rectangles from those numbers and CSS-only margins would move the panes out from under the shapes.

A theme of your own

So is the type

:root {
  --mz-font: Inter, sans-serif;
  --mz-font-display: "Space Grotesk";
  --mz-h1-weight: 300;
  --mz-h2-weight: 400;
  --mz-h2-border: none;
  --mz-h2-rule-w: 64px;
  --mz-h2-rule-h: 4px;
  --mz-h2-rule-gap: 14px;
}

This is what theme: mirzam sets — the rule under the heading above is that last group.

The faces, a size, weight, tracking and leading per heading level, and the marks: --mz-strong-*, --mz-quote-*, --mz-code-bg, --mz-card-*, --mz-eyebrow-*, --mz-metric-*.

Every one carries today's value as its fallback, so a deck that sets none is unchanged — and one that sets some is an identity, not a repaint.

The whole list is in docs/syntax.md.

One class, in the deck

Bullets are a choice, not a default

.markers {
  --mz-bullet: "→  ";
  --mz-bullet-2: "·  ";

  --mz-marker: var(--mz-accent2);

That block is a <style> in this deck's own source — one or two classes do not need a file. A quoted string is a marker too, and carries its own trailing space, since the browser adds none after one.

Theming and settings13 / 16

Overflow

When a slide has too much on it

---
fit: shrink
---

::: pane notes {fit=shrink}

mirzam build long.md --fit shrink

Without it, a pane that overflows is clipped — the last line simply is not there, and nothing on screen says so.

fit: shrink scales the pane's text down until it fits instead. It is the right default for a document you converted rather than wrote, and the wrong one for a deck you are still editing, where you want to see the overflow and cut something.

node scripts/check-layout.mjs finds them either way.

Theming and settings14 / 16

Math

A dialect for formulas

---
math: typst
---

$x = (-b pm sqrt(b^2 - 4a c))/(2a)$

Which renders as:

x=−b±b2−4ac2a

  • Typst's math syntax, without the backslashes: a/b is a fraction, sqrt() is a root, Greek goes by name — alpha, Omega
  • Per deck, not per formula; the default is latex, so every existing deck reads as it always did
  • Both dialects render to MathML through the same path, so the result is identical down to the font
