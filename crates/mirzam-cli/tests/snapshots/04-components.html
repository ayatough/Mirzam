Layout

The layout is the ASCII you draw

+----------+----------+
|  head               |
+----------+----------+
|          |          |
|  left    |  right   |
|          |          |
+----------+----------+
  • Column widths follow the character widths
  • Row heights follow the line counts
  • Repeat a name to merge cells
  • Nothing to drag; the diff is readable

Same semantics as CSS Grid areas, so it is predictable.

Shapes

A diagram that lives in its pane

The previous slide placed its boxes in page coordinates. This one writes the shape block inside the fig pane, so every percentage is of the pane itself - at(50%, 12%) is the top centre of fig, wherever the grid puts it.

Resize the pane in the ASCII drawing and the whole diagram follows. Nothing clips at the pane's edges; past 100% is allowed, and deliberate.

Same DSL as the page-level form; only the coordinate space changes.

Diagrams

A diagram you did not draw

The two before this one were placed by hand, which is what you want when the arrows mean something. This one is a mermaid fence: the graph says what connects to what, and the layout is somebody else's problem.

It is drawn at build time by mermaid-cli, inlined as SVG in the deck's own colours - so it follows D into dark mode like everything else, and the deck is still one file. Without mmdc installed the fence stays a code block and the build says so; GitHub draws that same fence as a diagram anyway.

The renderer is a Node program the CLI shells out to, which is why it is not in the browser build.

Media

Video is a first-class citizen

The image syntax becomes a <video> on the file extension alone:

![Demo](media/demo.webm){.autoplay .loop .controls}
  • Flags: .autoplay, .loop, .controls, .muted
  • autoplay implies muted — browsers block audible autoplay
  • In the PDF it becomes its poster= frame
  • The file is embedded, so one HTML is the whole deck

mp4, webm, ogv and mov all work. The samples are webm because a Chromium built without proprietary codecs cannot play H.264.

A chime, three notes long

The sample is a wav because this repository ships no encoder; every format above takes the same path. Autoplay is deliberately not set here - a gallery deck that makes noise on arrival is a bad neighbour. poster= works too, since that is the word a video uses.

Annotations

Circle the thing you are talking about

Press → twice.

A mark is placed in percentages of the picture, and given an id — so the sentence can point at the region itself, not at a spot on the slide.

Annotations

A chart mark needs no coordinates

Every chart mark already has an id, so an annotation names one instead of measuring it. #load-0-2 is series 0, row 2 — the third node on a weekday.

  n-1, 41, 22
  n-2, 38, 24
  n-3, 74, 26

rect #load-0-2 : pad=10 step=1

The next slide changes two numbers in the CSV. The annotate block is identical.

Annotations

Change the numbers; the box follows

Two numbers changed in the CSV above, and the annotate block did not. The box is still around #load-0-2 — which is now the short bar, so it shrank and moved down with it.

  n-1, 77, 22
  n-2, 38, 24
  n-3, 19, 26

rect #load-0-2 : pad=10 step=1

A hand-measured rectangle would now be pointing at empty air.

Annotations

Point at a phrase, not across the slide

An arrow from a sentence to a figure has to leave the text, cross the slide, and arrive somewhere meaningful.

Marking both ends at the same moment, in the same colour, says it with nothing travelling between them — and it survives an edit to the sentence.

Marking both ends [at the same moment]{#s-moment}

```annotate
highlight #s-moment : step=1
underline #s-colour : step=2
box       #s-edit   : step=3 pad=4
```

highlight, underline and box take an #id and nothing else: where the words are is the browser's business.

No target: line: every item is anchored.

Three clicks. The underlined phrase wraps, so watch it marked line by line rather than as one box swallowing the gap.

References

A picture says where it came from

![Fig. 3](fig3.png){caption="What it shows"}
![Fig. 3](fig3.png){credit="[@vaswani2017]"}
  • caption= is the author's sentence about the picture; credit= is where it came from, set small and quiet under it. Either, or both on one reference
  • A [@key] in a credit is a citation like any other: it numbers with the rest, and the entry lists this slide among the ones that cited it
  • Free text works too — credit="Photo: NASA/JPL"

The credit is the line an audience never reads out loud and a slide has to carry anyway. It is why the entry on the next slide has two backlinks and not one.
